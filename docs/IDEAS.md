## 읽기 전 사전지식 카드

**문제**: 논문을 자주 읽지 않는 사람은 문장 하나하나보다 "이 논문을 읽으려면 무엇을 알아야 하는지"를 모르는 데서 막힌다.
문장 해설은 막힌 뒤에 돕지만, 사전지식 카드는 막히기 전에 돕는다.

**현재 동작과의 차이**: 지금은 논문을 가져올 때 LLM이 미리 읽지 않는다(로컬 파싱만, LLM 호출 0회).
해설은 사용자가 고른 부분만 그때 만든다. 사전지식 카드는 데이터 뼈대 카드와 함께 논문 단위로 한 번 만드는 첫 LLM 기능이 된다(3.5단계 "읽기 전 준비").

### 안
- **입력**: 초록 + 목차(제목 목록) + 서론 + 결론, 약 4천 토큰. 필요한 개념은 대부분 여기에 드러나므로 논문 전체를 보내지 않는다.
- **모델**: Sonnet 5.5. 논문당 한 번이고 정확도가 중요해서 Haiku보다 Sonnet이 낫다. 예상 2~3¢.
- **출력**: 개념 3~6개. 각 개념마다
  - 무엇인지 (2문장)
  - 이 논문에서 왜 필요한지
  - 어디서 나오는지 (섹션, 클릭하면 이동)
- **개인화**: 사용자 프로필을 넣어 이미 알 만한 개념은 빼고 고른다.
- **캐시**: 논문 + 프로필 기준으로 저장. 다시 열면 무료.
- **위치**: 논문을 열고 아직 아무것도 고르지 않았을 때 오른쪽 패널의 첫 화면.
- **나중 연결**: 4단계의 아는 용어(KnownTerm)와 이으면 다른 논문에서 이미 본 개념에 "전에 봤어요" 표시.

### 정할 것
- **생성 시점**: 버튼(추천, 덮을 논문엔 비용 없음) / 가져올 때 자동(논문당 2~3¢ 항상 발생)
- **순서**: 4단계(관련 언급) 전에 할지
- **입력 범위**: 위 4천 토큰으로 충분한지, 논문 전체(약 8~10¢)가 필요한지 — 몇 편으로 비교해 본다

## 데이터 뼈대 카드

**문제**: 논문이 "뜬구름 잡는" 느낌을 주는 가장 큰 이유는 데이터가 안 보여서다. 문장 해설은 아래에서 위로 읽는 도구라서,
해설을 아무리 봐도 "그래서 이 연구의 데이터가 뭔데?"라는 뼈대가 잡히지 않는다.

**출발점이 된 조언** (요지): Methods와 표를 먼저 보며 네 가지를 뽑아라 — 입력(X)이 정확히 어떤 측정값인지, 출력(y)이 무엇인지,
샘플이 몇 개인지, 검증을 어떻게 했는지. 식품 분야는 샘플이 수십 개 수준인 경우가 많아 화려한 모델보다 데이터 구조와 검증 방식이 중요하다.
이걸 정리하면 의뢰를 받을 때 "어떤 데이터를 받아야 하는지"를 먼저 물을 수 있다.

### 안
| 항목 | 내용 |
|---|---|
| 입력 X | 측정값·처리 조건과 단위 (예: PEF 처리 조건, PAW 처리, 염수 NaCl 5·10%, 절임 시간) |
| 출력 y | 예측·측정 대상 (예: 고형분 증가 SG, 수분 손실 ML) |
| 샘플 수 | 원 시료 수 / 반복 수 / 총 데이터 포인트를 **구분**. 명시가 없으면 실험 설계로 계산하고 "추정"과 계산식 표시 |
| 분할·검증 | 학습·검증·테스트 비율, 교차 검증, 외부 검증 여부, 분할 단위(시료·배치·시점) |
| 평가 지표 | RMSE, R² 등과 보고된 값 |
| 주의 신호 | 판단은 사람이 하되 흔한 위험을 짚는다: 작은 n 대비 복잡한 모델, 같은 배치에서 뽑은 테스트셋, 반복 측정값이 학습·테스트에 섞였을 가능성, 테스트셋 크기가 너무 작음 |
| 의뢰 시 물어볼 질문 | 빈 항목·주의 신호로부터 "이 연구를 의뢰받는다면 먼저 확인할 것" |

- 모든 항목에 **근거 문장**(클릭하면 원문 위치로 이동) 또는 **"논문에 명시 안 됨"**을 붙인다. 명시가 없다는 사실 자체가 가장 값진 신호다.
- 데이터가 없는 논문(이론·리뷰)은 "해당 없음"으로 답한다.
- 사전지식 카드와 함께 **"읽기 전 준비"** 화면 하나로 묶는다. 논문을 열고 아무것도 고르지 않았을 때의 첫 화면.
- **입력**: Methods 계열 섹션(`Materials and methods`, `Methods`, `Experimental`, `Data` 등 제목으로 찾음) + 표·그림 캡션 + 표 내용(아래).
  찾지 못하면 참고문헌을 뺀 본문 전체. **모델**: Sonnet 5.5, 논문당 1회 저장. 예상 3~5¢(표 이미지 포함 시 +1~2¢).

### 현실적인 약점과 극복 방법

**1. 표를 제대로 읽지 못한다** — 가장 큰 약점. 샘플 수·처리 조건·결과 수치는 표에만 있는 경우가 많은데,
지금 파서는 표를 구조화하지 못한다(작은 셀은 `figure`, 큰 셀은 `paragraph`로 흩어짐).
- **1차: 표 영역 찾기.** 캡션(`Table N`)을 기준점으로, 캡션 아래(또는 위)에서 다음 본문 문단 전까지의 블록을 한 영역으로 묶어 `table` 블록을 만든다.
  수식을 번호 `(n)` 기준으로 합친 것과 같은 방식이다.
- **실제 확인 결과 (구현 전 점검)**: `find_tables()`는 식품 학술지 논문 2편에서 표를 하나도 찾지 못했고 ML 논문에선 그래프를 표로 오인,
  글자 배치 기반은 페이지 전체를 표로 잡았다. 그래서 아래 "텍스트" 경로는 쓰지 않고 **이미지 경로만** 쓴다.
- **2차: 표 내용 얻기 — 두 경로를 함께 쓴다 (계획 당시 안).**
  - 텍스트: PyMuPDF의 `page.find_tables()`로 셀 구조를 뽑아 마크다운 표로 만든다. 선이 그어진 표에 강하고 토큰이 적다.
  - 이미지: 표 영역을 잘라 이미지로 보낸다(수식 이미지와 같은 경로). 선이 없는 표, 병합 셀, 첨자가 많은 표에 강하다. 표 하나에 대략 수백~천여 토큰.
  - 텍스트 추출이 성공하면 텍스트를, 셀이 비거나 깨지면 이미지를 보낸다. 판단 기준(빈 셀 비율 등)은 실제 논문 몇 편으로 정한다.
- **회전된 표**(가로로 눕힌 페이지)는 파서 v3에서 좌표를 바로잡았으므로 같은 방법이 적용된다.
- 표 영역이 생기면 사용자에게도 쓸모가 있다: 표를 클릭하면 수식처럼 원본 이미지와 해설을 보여줄 수 있다.

**2. 뽑은 값이 틀릴 수 있다** — LLM이 숫자를 잘못 옮기거나, 없는 내용을 그럴듯하게 채울 수 있다.
- **근거 검증**: 항목마다 근거 문장 id와 짧은 원문 인용을 받아, 인용이 실제 문장에 있는지 정규화 매칭으로 확인한다(Q&A 계획의 출처 검증과 같은 장치).
  확인 실패 항목은 "근거 미확인"으로 표시한다.
- **숫자 대조**: 답에 나온 숫자(n=96, 70/15/15 등)가 근거 문장이나 표 텍스트에 실제로 있는지 확인한다. 없으면 "계산·추정값"으로 표시하고 계산식을 함께 보여주게 한다.
- **"명시 안 됨"을 정답으로 허용**: 프롬프트에서 빈칸을 채우지 말라고 명시하고, 모르면 "명시 안 됨"이 맞는 답이라고 알려준다.
- 3단계에서 Haiku가 단위를 단정했던 사례가 있어 이 기능은 Sonnet을 쓴다.

**3. 필요한 정보가 논문 밖에 있다** — 보충 자료(Supplementary), 이전 논문, 공개 데이터 저장소.
- 본문에 "Supplementary", "Table S1", "data available at" 같은 언급이 있으면 "보충 자료에 있을 수 있음"으로 표시하고 해당 문장으로 연결한다.
- 보충 자료 PDF를 함께 올리는 기능은 나중에 검토한다.

**4. Methods를 못 찾는다** — 섹션 이름이 제각각이거나(예: "2. Experimental design") 목차 인식이 실패한 경우.
- 제목 키워드로 찾고, 실패하면 참고문헌 앞까지 본문 전체를 보낸다(비용 증가: Sonnet 약 8~10¢).
- 어느 범위를 보냈는지 카드에 표시해서 사용자가 판단할 수 있게 한다.

**검증 방법**: 데이터가 있는 논문 3~5편(radish 포함)으로 사람이 직접 뽑은 정답과 비교한다. 항목별 정확도와 "명시 안 됨" 판정 정확도를 본다.

## 번역 비용 줄이기

**관찰** (3단계 실측): 문단 번역 한 번의 입력 939 토큰 중 약 790 토큰이 시스템 프롬프트와 지시문이고, 문단 자체는 150 토큰 정도다.
문단을 하나씩 번역하면 매번 같은 지시문 값을 낸다.

**안**
- 화면에 보이는 문단 여러 개를 한 번에 번역한다 (지시문 비용을 나눠 냄). 논문 전체 번역은 약 26¢ → 10¢대로 줄 것으로 예상.
- 논문 전체 번역이 필요하면 Message Batches API로 보낸다 (비동기, 비용 50%).
- 번역용 시스템 프롬프트를 해설용과 분리해 짧게 만든다.

**보류 이유**: 지금은 번역을 버튼으로만 하므로 전체 비용에서 차지하는 비중이 작다. 전체 번역 기능을 넣을 때 다시 본다.

## 유료화 검토

> 2026-10-06 기준 참고용 계산. 지금은 유료화·대중 공개 계획이 없다. 환율 1달러 = 1,400원.

### 편당 원가 (3단계 실측 기반 추정)
| 읽는 방식 | 사용량 가정 | LLM 비용 |
|---|---|---|
| 훑어보기 | 문장 해설 10, 단어 10, 더 자세히 2 | 약 10¢ (140원) |
| 꼼꼼히 | 문장 40, 단어 30, 수식 5, 더 자세히 5, 번역 20문단 | 약 37¢ (520원) |
| 전부 다 | 전체 번역 145문단, 문장 60, 단어 50, 수식 13, 더 자세히 15 | 약 90¢ (1,260원) |

1회 단가 실측: 문장 해설 0.40¢, 단어 0.27¢, 수식 0.31¢, 문단 번역 0.18~0.22¢ (Haiku 4.5), 더 자세히 1.5¢ (Sonnet 5.5). 기준 논문은 16쪽 radish 논문.

### 편당 1,500원일 때
```
판매가               1,500원
- 부가세 10%         −136원
- 결제 수수료 3.3%    −45원
- LLM 원가(꼼꼼히)   −520원
= 편당 남는 돈        약 800원
```
- 고정 운영비 월 15만 원(서버·DB·스토리지) → 월 약 190편이 손익분기. 인건비 월 300만 원까지 → 월 약 3,900편.
- "전부 다" 읽는 사용자는 원가 1,260원이라 거의 남지 않는다. 편당 정액은 많이 쓰는 사람일수록 손해.

### 과금 방식
- **편당 결제는 불리**: 소액 결제 경험이 번거롭고, 해외 결제(Stripe 등)는 건당 고정 수수료가 있어 성립이 어렵다.
- **충전식 크레딧 (추천)**: 기능별 차감(예: 해설 1, 더 자세히 4, 번역 0.5). 원가 구조가 그대로 반영된다.
- **월 구독**: 예) 월 9,900원에 "꼼꼼히 기준 월 15편" 한도. 한도를 다 쓰지 않는 사용자가 많아 평균 마진은 계산보다 높아지는 것이 보통.

### 원가를 낮출 여지
- **사용자 간 결과 공유**: 인기 논문은 다른 사용자가 만든 해설을 재사용. 지금은 캐시 키에 프로필 전체(자유 텍스트 배경지식)가 들어가 공유가 안 된다.
  공개 서비스라면 설명 수준(3단계)만 키에 넣는 모드를 검토.
- [번역 비용 줄이기](#번역-비용-줄이기).

### 가격을 정하기 전에
- 위 숫자는 실측 5건과 가정한 사용량으로 만든 추정이다. 무료 베타로 `LlmCall` 기록을 모아 **실제 편당 원가 분포**를 보고 정한다.

### 라이선스: PyMuPDF (AGPL-3.0)
AGPL은 수정본을 배포하거나 **네트워크로 서비스를 제공할 때** 그 서비스의 전체 소스를 같은 라이선스로 공개하라고 요구한다.
상황별로 정리하면 (법률 자문 아님, 실제 공개 전에 확인 필요):

| 상황 | 문제 여부 |
|---|---|
| 지금처럼 혼자 로컬에서 사용 | 문제없음 |
| 공개 저장소에 소스를 올려 둠 (현재) | 문제없음. 단, 저장소에 아직 라이선스 파일이 없다 — 공개 범위를 정할 때 함께 정한다 |
| 소스를 AGPL로 공개한 채 서비스 운영 (무료·유료 모두) | 가능. 수정 사항까지 계속 공개해야 한다 |
| 소스 비공개로 서비스 운영 | 상용 라이선스 구매(Artifex 견적) 또는 파서 교체 필요 |

**파서 교체는 어렵지 않게 설계돼 있다**: 파서는 `app/parsing/`의 `ParsedDocument`를 돌려주는 함수 하나로 분리돼 있다.
후보는 pdfplumber(+pdfminer.six, MIT), pypdfium2(Apache-2.0/BSD), Docling(MIT, 무겁다).
글자 크기·색·기준선·회전 정보를 얻을 수 있는지가 관건이다(첨자 표시, 숨은 텍스트 필터, 회전 페이지가 이 정보에 의존).
같은 테스트(`tests/test_parser*.py`)와 실제 논문 4편으로 결과를 비교해 교체 여부를 판단한다.
